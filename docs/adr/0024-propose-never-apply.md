# 0024 — Propose, never apply

Status: Accepted
Date: 2026-08-09
Level: [22](../roadmap/level-22/spec.md)

## Context

[Level 13](../roadmap/level-13/spec.md) named this in its non-goals: *"the agent
reviews, it does not write the patch."*

Nine levels later the gap is the obvious one. The reviewer knows a `hashlib.md5`
call should be `sha256`, knows the file, knows the line — and writes "consider
using SHA-256". That is arithmetic reported as advice, and every source that
describes an agentic system expects it to *act*.

The reason it was left out has not weakened. A patch generated by a language
model and then applied is a change nobody reviewed, inside a system whose entire
argument is that a model may not decide anything. [ADR 0004](0004-findings-drive-the-gate.md)
keeps a model out of the verdict; [ADR 0022](0022-a-verdict-that-can-be-audited.md)
made a record that says otherwise impossible to build. A model-authored patch
applied by a bot would walk around both of them.

## Decision

### Propose. Never apply.

The system offers an edit. A person applies it, or does not.

Nothing in this package writes to a checkout, runs `git`, or calls an API that
changes a repository. That is asserted rather than promised:
`tests/unit/test_architecture.py` parses the three remediation modules and fails
if they import `subprocess`, `shutil`, `os` or a git binding, if they call
anything that writes, or if the forge port grows a method beyond commenting.

A sentence saying "we never apply" stays true only until somebody two levels
later adds `subprocess.run(["git", "apply", …])` to fix a ticket. A test stays
true or goes red.

### Recipes, not generation

Three deterministic transformations ship:

| Rule | Edit | Declines when |
|---|---|---|
| `SAST.WEAK_CRYPTO` | `hashlib.md5(`/`sha1(` → `hashlib.sha256(` | the line is already `sha256` |
| `SAST.INSECURE_DESERIALIZATION` | `yaml.load(` → `yaml.safe_load(` | the call is `pickle.loads` — there is no one-line change that makes it safe |
| `SAST.HARDCODED_SECRET` | `NAME = "…"` → `NAME = os.environ["NAME"]` | the file does not already import `os` |

Each reads **the line its finding named**, never the file. A recipe that
searched for its own pattern would edit a line the finding said nothing about,
and the reader would have no way to connect the two.

The declines are the design. A recipe that guesses produces a button that breaks
a build, and one broken button costs every future suggestion its credibility.

### Validated by applying it

A suggestion is a claim about what a file would look like. The cheap way to
check a claim like that is to make it true and look: the service applies the
edit in memory and re-parses the result, and discards the suggestion if the file
would no longer parse.

What is *not* checked is semantic equivalence. `md5` → `sha256` changes
behaviour on purpose — a stored digest will not match — and the finding's
remediation text is where that belongs.

### Only a deterministic producer may author one

Level 20 attributes a finding to its producer from the rule namespace, and
treats an unregistered one as an agent. A suggestion inherits that rule: an
agent-produced finding never yields an applicable edit, however plausible its
prose.

A change a human applies in one click is a change they will trust roughly as
much as the gate. The same restriction belongs behind both.

### Posted as diff notes

GitLab renders a fenced ` ```suggestion:-a+b ` block as an applicable change
**only in a note attached to the line**. The same block in the review comment is
a code block somebody has to retype, which is the difference between a feature
and a decoration.

So suggestions go out as discussions anchored on the line, and the review comment
says how many were posted. Posting a note is still commenting: the position
carries three commit SHAs and no write.

## Consequences

A reviewer reading a merge request sees a button next to the line. Clicking it
is their decision, recorded under their name, in a commit they authored.

The decision record gains what was suggested — rule, location, recipe. Not the
replacement text: it is derived from the file under review, and five levels have
kept that out of the artefacts.

Three recipes is not many. A rule with none produces exactly the advice it
always did, which is the honest failure mode: the feature is absent rather than
approximate.

A forge that cannot anchor a note on a line — an older instance, an unusual
merge-request state — logs that it cannot and publishes the review unchanged.
The suggestion is an improvement to a comment, never a precondition for it.
